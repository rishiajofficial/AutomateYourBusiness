## Article Structure

Each article follows this structure:
- **Title:** Problem-first, long-tail SEO
- **Insight Origin:** What triggered the idea
- **Problem Breakdown:** Non-generic, experiential
- **Build Philosophy:** Why this approach
- **Key Learnings:** Bulleted, practical
- **Who This Is For:** Clear audience definition
- **Related Projects:** Internal links
- **Future Extensions:** What's next

## Tone & Style

- Builder's journal: honest, non-marketing, insight-driven
- Problem-first: starts with the real problem, not the solution
- Experiential: based on real observations, not theory
- SEO-optimized: long-tail keywords, natural headings, no fluff

## Adding New Articles

When a new project is added or significantly updated:

1. Create a new markdown file: `insight-<project-name>.md`
2. Follow the structure above
3. Include internal links to related projects
4. Update this README with the new article
5. Commit with message: "Add blog article for [project name]"

## SEO Considerations

- Use long-tail keywords naturally
- H2/H3 headings for structure
- Internal links to related projects
- No AI-sounding phrases or fluff
- Problem-first titles that match search intent
